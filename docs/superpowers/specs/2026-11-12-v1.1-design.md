# Design Spec: poRi v1.1 (Full Subject Model Tests, History Analytics, Study Planner & Offline Packs)

**Date:** 2026-11-12
**Branch:** `feat/v1.1` (branched from `feat/mvp-completion`)
**Parent Spec:** [2026-11-08-pori-platform-design.md](./2026-11-08-pori-platform-design.md) (Section 0 v1.1 scope)

---

## 1. Intent, Goals & Constraints

### Intent
Implement the full **v1.1** feature set defined in Section 0 of the poRi platform design specification:
1. **Full Subject Model Tests & History Analytics:** Support `SUBJECT_TEST` model exams spanning all chapters of a subject, percentile ranking against peer attempts, and a dedicated exam history + score trend chart on `/progress`.
2. **Study Planner & Reminders:** Add a persistent daily/weekly study planner (`StudyPlanTask` model, smart auto-schedule generator prioritizing weak/unresolved topics, in-app due reminders, and optional Web Notifications).
3. **Offline Packs, Offline Tests & Result Sync:** Let students download complete chapter packs (lessons + practice/test questions) into IndexedDB, study/practice/take timed chapter tests offline, and automatically synchronize offline completions and test results via `POST /student/sync-offline` when connectivity returns.

### Non-Goals & Strict Boundaries
- **No Authorization Changes:** Do **NOT** modify `apps/api/src/modules/auth/*`, JWT guards/strategies, OTP verification, or SMS delivery (the user plans to replace the authorization system separately).
- **Deferred to v1.2+ / Phase 2–3:** Flutter app, verified multi-board 2020–2024 paper archives, multi-subject simultaneous exam rehearsal, audio lessons, AI grading, multiplayer duels, and billing.
- **Dev Server Safety:** Do NOT cache `_next/static` aggressively inside localhost dev mode in `sw.js`, avoiding stale chunk mismatches during local Next.js dev.

### Backward-Compatibility Guarantees
- `StartExamDto` preserves existing `CHAPTER_TEST`, `TOPIC_TEST`, and `WEAK_AREA` validation (still requiring `chapterId` for non-subject tests); only `SUBJECT_TEST` allows omitted `chapterId`.
- `GET /practice/chapter/:chapterId/questions` (`MCQ`) continues stripping `isCorrect` and `explanation`. Explicit offline bundles live exclusively on `GET /curriculum/chapter/:chapterId/offline-pack`.
- All new Prisma queries (`examSession.findMany` for percentiles, `studyPlanTask`, etc.) include safe method-existence/catch guards so unit-test Prisma mocks continue passing cleanly.

---

## 2. Approaches Considered

1. **Pure client-only IndexedDB + localStorage planner without backend persistence** — Faster, but planners wouldn't sync across browsers and offline test results couldn't enter backend `ExamSession` / `RevisionMistake` analytics.
2. **Additive Schema + Modular NestJS Planner/Offline Endpoints + Shared Exam Runner & IndexedDB Layer (Selected)** — Extends `ExamService` with `SUBJECT_TEST`, percentiles, and `GET /exam/history`; adds `StudyPlanTask` + `PlannerModule` (`OptionalJwtAuthGuard` — zero auth changes); adds `GET /curriculum/chapter/:chapterId/offline-pack` and `POST /student/sync-offline`; extracts shared `ExamRunnerClient` for both `/exam/[chapterId]` and `/exam/subject/[subjectId]`; and adds IndexedDB + safe production `sw.js` offline engine.

## 3. Component Design

### Track 1: Subject Model Tests, Percentiles & History Trends
- **Shared Types (`@pori/shared`):** Add `SubjectTestHistoryResponse`, `ExamTrendPoint`, `StudyPlanTaskDTO`, `OfflineChapterPackDTO`, and `OfflineSyncPayload`.
- **Backend (`ExamModule`):**
  - `StartExamDto`: Allow `'SUBJECT_TEST'` in `@IsIn(['CHAPTER_TEST', 'TOPIC_TEST', 'WEAK_AREA', 'SUBJECT_TEST'])`, make `chapterId` `@ValidateIf((o) => o.testType !== 'SUBJECT_TEST')`, bump `questionLimit` max to `100`.
  - `ExamService.startExam`: For `'SUBJECT_TEST'`, validate subject existence when mocked or query published MCQs where `topic: { chapter: { subjectId: dto.subjectId } }`, default `questionLimit` to `25` if omitted, save `chapterId: null`.
  - `ExamService.submitExam` & `getSession`: Compute `percentile` (`Math.round((scoresBelowOrEqual / totalCompleted) * 100)`) safely when peer completed sessions exist (`>= 1`).
  - `GET /exam/history`: Returns `{ items, summary: { totalTests, averageAccuracy, bestScorePercent, subjectTestsCount }, trend }` filterable by `subjectId` and `testType`.
- **Frontend:**
  - Extract shared `ExamRunnerClient` from `/exam/[chapterId]` supporting both `chapterId` mode (`CHAPTER_TEST`/`TOPIC_TEST`/`WEAK_AREA`) and `subjectId` mode (`SUBJECT_TEST`, default 25/50/All questions).
  - Add `/exam/subject/[subjectId]/page.tsx` and CTA links in `/curriculum/[subjectId]` and `/dashboard`.
  - Display percentile badge in `ExamResultView`.
  - Upgrade `/progress`: Fetch `GET /exam/history` (merged with `examHistory` store fallback), add exam-type filter pills, SVG score trend line chart, and summary KPIs.

### Track 2: Study Planner & Reminders
- **Prisma (`schema.prisma`):** Add `StudyPlanTask` (`id`, `userId`, `subjectId?`, `chapterId?`, `topicId?`, `titleBangla`, `scheduledDate`, `reminderTime?`, `targetType`, `completed`, `completedAt?`, `createdAt`, `updatedAt`).
- **Backend (`apps/api/src/modules/planner`):**
  - `PlannerController` guarded by `OptionalJwtAuthGuard` (works seamlessly with existing tokens/guest JWTs without touching `AuthModule`):
    - `GET /planner` -> list tasks + `todayDueCount`
    - `POST /planner` -> create custom task
    - `POST /planner/auto-generate` -> builds a 7-day plan from unresolved `RevisionMistake` topics + remaining chapter topics
    - `PATCH /planner/:id` -> toggle `completed` / reschedule
    - `DELETE /planner/:id` -> remove task
- **Frontend:**
  - Extend `useUserStore` with `studyPlanTasks` + CRUD actions syncing with `/planner` when token present.
  - Create `apps/web/src/lib/reminders.ts` computing due tasks (`scheduledDate === today && !completed`) and active time reminders, plus browser Web `Notification` permission helper.
  - Create `/planner` page (`apps/web/src/app/planner/page.tsx`) with Today/Week agenda, custom task creator, `"স্মার্ট ৭-দিনের রুটিন তৈরি করো"` button, reminder toggle, and direct launch links.
  - Add compact `"রুটিন"` icon link in `PersistentNav` utility area and a "Today's Study Plan & Due Reminders" card on `/dashboard`.

### Track 3: Offline Chapter Packs, Offline Exam Runner & Sync Queue
- **Backend (`CurriculumModule` & `StudentModule`):**
  - `GET /curriculum/chapter/:chapterId/offline-pack`: Fetches `PUBLISHED` lessons & questions for every topic in the chapter, packaging `{ chapterId, titleBangla, versionHash, downloadedAt, lessons, questions }` (falls back gracefully or 404s if chapter invalid).
  - `POST /student/sync-offline`: Accepts `{ lessonCompletes, practiceAttempts, examSubmissions }`, deduplicating/persisting into `EventLog`, `RevisionMistake`, and `ExamSession` (`status: 'COMPLETED'`).
- **Frontend (`apps/web`):**
  - `apps/web/src/lib/offline-store.ts`: Promise-based IndexedDB wrapper (`pori-offline-db` with clean `localStorage` fallback for non-IDB environments) storing `chapterPacks` and `syncQueue`.
  - `apps/web/public/sw.js` + `apps/web/src/lib/sw-register.ts`: Registers Service Worker on non-localhost or production origins and handles offline app shell/route caching without breaking `next dev` HMR.
  - `apps/web/src/components/navigation/offline-sync-banner.tsx`: Mounted in `AppShell`, watches `online`/`offline` status + pending `syncQueue` count, auto-flushes `POST /student/sync-offline` when online, and offers manual sync trigger.
  - Wire `/curriculum/[subjectId]` chapter cards with `"অফলাইন ডাউনলোড"` / `"অফলাইন সংরক্ষিত"` buttons; wire `/lesson/[topicId]`, `/practice/[chapterId]`, and `ExamRunnerClient` to load cached IndexedDB packs & grade exams locally when offline, queuing results into `syncQueue`.
